## 2. 構成と実行モデル

### 2.1 プラットフォーム

- IDEはネイティブC++／Win32 x86。現行Windowsのビルドホストで `v141_xp`、`WINVER`／`_WIN32_WINNT=0x0501`、PEサブシステム `5.01` の組み合わせを検証する。C++言語機能は当該コンパイラーの実装範囲内に制限する。
- CRTはリリース版の静的リンクを第一候補とする。C++標準ライブラリや依存モジュールを含めてインポートを点検し、クリーンなXPで起動することを必須とする。`/MT` 指定だけでXP互換・追加DLL不要とは判定しない。SSE2の採否は実機CPUを確認して固定する。
- GUIはUnicode版Win32 APIとGDI、Classic表示の共通コントロール。Windows Ribbon Framework、.NET、常駐サービス、オンライン認証を必須にしない。

### 2.2 モジュール境界

以下は責務の名称であり、現時点で既存のソースファイルではない。

| モジュール | 入出力・責務 |
| --- | --- |
| `Win32Host` | ウィンドウ、リボン、操作状態、ファイルダイアログ、Unicodeパス、設定、ログ表示。音声デバイス処理をUIスレッドで待たない。 |
| `BasicCore` | UTF-8ソースの字句解析・診断・補完、CF-2000機種プロファイル、トークン化／逆変換、出力行マップ。音声・エミュレーター・UIから独立。 |
| `TapeCore` | `PCM ↔ ブロック ↔ テープファイル` の変換、FSK、WAV・CAS解析、ブロックの位置と異常情報。WinMMに依存させない。 |
| `AudioWinMM` | 入出力機器列挙、形式照会、PCM入出力、固定長バッファの管理、レベル集計、停止・後片付け。 |
| `OpenMsxAdapter` | 別プロセス起動、ローカル名前付きパイプ、XML応答と実行イベント、タイムアウト、デバッガーからの読み取り専用変数参照。 |
| `Packaging` | 固定バージョンの再現ビルド、依存ライセンス、オフラインインストーラー、導入・削除試験。 |

UIスレッドはコマンドと表示を担当。音声処理は専用ワーカーで、WinMMのイベント通知と事前確保済みバッファを使用する。PCM保存・復号は機器へのバッファ再投入を待たせず、処理待ちのキューに上限を設ける。キューが溢れたら失われた処理（録音または復号）と位置を表示し、欠落のある結果を正常完了にしない。復号が追いつかないだけなら、正常に保存できたWAVを後から復号できる。インポートとデバッグ通信も中断・失敗をUIへ通知する。

## 3. カセットと音声

### 3.1 接続・キャリブレーション

1. MSXの通常音声出力とデータレコーダー端子を混同しない。標準DIN配線では `CMTOUT` がPC入力側、`CMTIN` がPC出力側。ケーブルの `MIC`／`EAR` は録音機側での用途表示であり、現物の結線を確認する。`REM` はPCにつながない。
2. マイク入力仕様、端子の給電、結線、ドライバーの入力選択を確認する。可能ならマイクブースト、AGC、ノイズ抑制、マイクの再生監視を無効にする。PCの出力は低い音量から調整する。入力段で歪む構成ではデジタル減衰を解決策とせず、仕様に適合する減衰・DC遮断アダプターを試す。なお不安定ならXPで実測済みのライン入力機器を代替候補にする。
3. `CSAVE"TEST",1` と `CSAVE"TEST",2` で、同じ既知BASICの独立した基準録音を作る。録音ごとにPC・音源・ドライバー、設定、接続、レベル、波形の特徴を記録する。反対方向はCF-2000が `CLOAD"TEST"` で待機してから送信する。ロード、`LIST`、`RUN`、必要な再保存を実機で確認する。

### 3.2 取込・送信・状態

- 録音はRIFF/WAVE、PCM符号付き16 bit little-endian、48,000 Hz、モノラル、96,000 byte/s（1時間約346 MB）。明示指定した機器で `waveInOpen` の形式照会と実オープンを確認する。48 kHzモノラルが拒否されたら同レート・同ビット深度のステレオから有効な1チャンネルを選択できる。他レートで録音して48 kHzと記録しない。`WAVE_FORMAT_DIRECT` はACM変換に関する指定であり、ハードウェア内部まで変換なしとは証明しない。
- 選択した入力チャンネルの原サンプルをWAVに保存し、クリップ補正・DC除去・正規化は保存前に行わない。送信波形も48 kHzで生成し `waveOutOpen` で再生する。必要に応じてステレオ向けの再生チャンネルを調整するが、左右出力を短絡する結線を前提としない。再生が成功しても受信成功とは表示しない。
- 状態: `待機` → `入力レベル確認`／`録音（復号する・しない）`／`送信` → `停止処理` → `待機`。保存済みWAVの復号は独立したオフライン処理。初版は1回に1つのハードウェア音声操作とし、同時録音・送信を要求しない。
- 録音はストリーム書き込みとし、PCM全量をメモリに保持しない。正常停止または可能な中断では書き込み済みサイズでWAVを閉じる。ディスク満杯・サイズ上限・機器切断を区別し、救出可能な録音を明示する。1ファイルの初期上限はデータ2 GiB未満で、超過前に正常に切り上げる（暫定）。既存WAVやCASを無確認で上書きしない。

### 3.3 ボリュームインジケーター

| 項目 | 表示・挙動 |
| --- | --- |
| 入力 | `入力（マイク）` と機器／チャンネル、PCMピークのdBFS、ピークホールド、デジタルクリップのラッチ。無音時は `−∞` または `信号なし`。デジタルの上限到達と、アナログ歪みの疑いは区別し、後者を断定しない。 |
| 出力 | `送信（デジタル）` と再生予定PCMのレベル。サウンドカードの端子電圧、OSのミキサー後の音量、実機の受信状態は表さない。 |
| 初期値（暫定） | GUI更新約15 Hz、ピーク保持1秒、入力ピークの目安 `−18～−6 dBFS`、`−3 dBFS` 以上はレベル過大に近い旨を表示。実際のPCMレール到達は別警告。無入力や同期の判定閾値は基準波形から決める。 |
| 操作 | 録音せずに入力を監視、クリップ表示の解除、入力機器の選択、OSの録音ミキサーを開く。ミキサーが制御を提供しない場合は手動調整を案内。音声監視をスピーカーへループしない。 |
| 可読性 | 色に加えて `信号なし`、`同期中`、`入力過大`、`同期失敗` を文字表示。レベルの適正とFSKの同期・データ一致は別状態。 |

### 3.4 信号処理

| ボーレート | ビット0 | ビット1 | 48 kHz時の公称サンプル数 |
| --- | --- | --- | --- |
| 1200 | 1200 Hzを1周期 | 2400 Hzを2周期 | 40サンプル／ビット |
| 2400 | 2400 Hzを1周期 | 4800 Hzを2周期 | 20サンプル／ビット、高周波1周期は10サンプル |

- 波形生成はMSX規格の長短リーダー、無音区間、1開始ビット（0）、8データビット（LSB先頭）、2停止ビット（1）を扱う。公称リーダーは長約6.7秒・短約1.7秒を出発点とし、CF-2000の実測で確認する。既存エミュレーターのCAS再生速度を実機転送規格として流用しない。
- 復号器は無信号 → リーダー候補 → 速度確定 → フレーム検出 → ブロック終了／再同期の状態遷移とする。長リーダーから1200／2400を推定し、短リーダーでも位相を同期する。DC除去、ヒステリシス付きのエッジ検出、半周期の追跡を第一候補とし、実測で不足する場合は帯域エネルギーを用いる方式も比較する。サンプル固定位置だけで判定せず、極性反転、レベル差、速度揺れ、欠損を回帰試験する。手動の速度指定は診断用に用意する。
- 失敗時はファイル中のサンプル位置／時刻、推定速度、失敗理由（リーダー未検出、フレームエラー、構造不正、途切れ等）を報告。未知データを推測で修復して正常にはしない。`構造を認識` と `照合済み` を区別し、後者は既知の期待値と比較したときだけ表示する。

### 3.5 ファイル形式

| 形式 | 初版の扱い |
| --- | --- |
| テープ上のトークン化BASIC | `CSAVE`／`CLOAD`。種別 `D3`、ファイル名、プログラム本体と終端。行リンク・行番号・数値表現をROMが保存したサンプルと照合し、アドレス値をPCファイル形式からそのままコピーしない。 |
| テープ上のASCII／データ | `SAVE`／`LOAD`・`OPEN` 系。種別 `EA`、データブロックとEOF規則を扱う。ASCIIの名称にかかわらず文字バイトの変換は明示的に行う。 |
| テープ上のバイナリ | `BSAVE`／`BLOAD`。種別 `D0`、開始・終了・実行アドレスおよびペイロード。開始・終了から計算した長さを検証する。IDEは取り出した機械語をホストPCで実行しない。 |
| CAS | 標準マーカーで区切られた論理テープ表現。複数ファイルを一覧表示・個別取出しできる。既知のブロック構造や長さを優先し、ペイロード内のマーカー様バイト列を無条件に区切りと見なさない。一般的なCASで原録音の速度・無音・波形は保持できないため、再生成時の速度は明示選択し、原音はWAVに残す。 |
| WAV | 出力は §3.2 固定。外部入力はまず48 kHz・16 bit PCMのモノラル／ステレオに対応、ステレオはチャンネル選択。RIFFチャンクの順序・長さ・境界と偶数バイトのパディングを検証。不正・途中切れ・未対応形式は診断して終了する。他形式への対応は初版外。 |

標準テープのファイル名フィールドは6バイト。テープ名とWindows側ファイル名は別項目とし、切り詰め・置換を黙って行わない。

## 4. BASIC、文字、およびUI

- 編集元はUTF-8 `.bas`（読み込み時のBOM可、保存はUTF-8 BOMなし）とし、行番号を保持する。WindowsパスとクリップボードにはUnicodeを使用。従来のMSX用データは通常のUTF-8ファイルとして自動解釈せず、テープ／MSXソースの取込みとして明示する。
- `BasicCore` の字句情報を色分け、補完、静的診断、トークン化で共用する。キーワード・関数、変数、行番号、文字列、コメント（`REM`／`'`）、`DATA`、コロン区切りを区別し、文字列・生データ・コメントの中で誤ってトークン化や補完を行わない。キーワード、引数ヒント、既出変数、`GOTO`／`GOSUB` などのリテラル行参照を初版の補完対象にする。
- 保存時には文書を壊さず、出力時に不正な行番号、重複、未定義の静的ジャンプ先、非対応命令、変換不能文字を行・桁付きで示す。実行時に決まるジャンプ・領域消費は静的に断定しない。実機初期化後の `PRINT FRE(0)` を機種プロファイルの参考値にし、トークン化本体・管理領域の見積もりと、変数・配列・スタックに別途必要な容量を区別する。
- 日本語IME、半角カナ、グラフィック文字、実機文字パレットを試験する。CF-2000の文字表に対してUnicodeとMSXバイト列の逆変換を定義する。同じ表示に対応する複数コードや未割当バイトは、変換不能を通知するか、取込時の原バイトを保持して往復できる表現を用いる。`?` への無言の置換はしない。漢字はPC上では編集・保存可能だが、標準CF-2000の出力には出せない旨を表示する。
- Scintillaは候補版をXPで実測して固定。日本語IMEの未確定文字、貼り付け、Undo/Redo、自動補完、ブレークポイント余白、複数バイト文字の桁位置を確認する。候補が不適合なら、代替コントロールで同じ合格条件を満たしてから採用する。
- リボンは `ファイル｜編集｜実行・デバッグ｜テープ`。折りたためる96 DPI基準のクラシックタブ、立体縁のコマンド群、標準システム色、小型の独自アイコン、ステータスバー。800×600で主要操作とメーターが隠れないことを必須とする。キー操作例: `Ctrl+Space` 補完、`F5` 実行／続行、`F9` ブレーク切替、`F10` 行ステップ。IME確定操作や標準フォーカス操作を奪わない。

## 5. デバッガー契約

- 基準バックエンドは公式openMSX 0.12.0 x86と、同タグに含まれる `National_CF-2000.xml`。タグでの設定の存在は確認済みだが、実行・デバッグは未検証。実機相当のRAM 16 KB、機種の選択、ROM照合を確認する。XPで起動・通信できない場合は初期工程で代替バックエンドを評価する。64 KB汎用機の成功を代替合格にしない。
- `-control pipe` のローカル名前付きパイプを使用し、TCPは使わない。XML応答と非同期イベントを区別し、開始・コマンド・終了にタイムアウトを設ける。利用者が入力したBASICソースは制御用Tclとして評価しない。読み込ませるプログラムとカセットの生成には、同じ `BasicCore` の出力を用いる。
- 実行は `未接続`／`起動中`／`実行中`／`停止中`／`切断・エラー` の区別を持つ。実行時のソーススナップショットを保持し、編集後の新しい本文に古い停止位置を表示しない。非対応ROM、起動失敗、アプリの外からの終了、転送失敗を区別して表示する。
- 行ブレークポイントは対象BASIC行の実行前に止まる。行ステップはコロンで区切られた同一行の後続文を原則通過し、次の動的な行到達で止まる。同一行への明示的な戻りも行到達として扱う。`H.NEWS` で得たイベントを候補とし、行番号だけでなく命令位置・実行境界も照合する。実際のフックとメモリレイアウトは使用するROMで検証する。`INPUT` などで次の行が実行されない場合、ステップ完了と見なさない。
- 停止中は整数・単精度・倍精度・文字列のスカラー変数を読み取り専用で表示する。未定義と取得不能を区別し、未対応の値を勝手にゼロとしない。実行時エラーは取得できたBASIC行とエラー情報を表示。配列の構造表示、変数書換え、Z80命令ステップ、任意式評価は初版外。

## 6. 配布と非機能要件

- Inno Setup 5.6.1 Unicode版を固定。インストール・アップグレード・アンインストールにネット接続不要。スタートメニュー、バージョン情報、使用許諾・依存ライセンス、オフラインの接続ガイドを付ける。アプリは通常ユーザーで実行でき、プログラムの設置先に設定や録音を書かない。既定では更新・アンインストールでユーザーのソース、CAS、WAVを削除しない。
- openMSXはユーザーが指定する別配布のバックエンドを第一候補とし、検証済みバージョンの導入手順を同梱する。BASIC ROMは同梱しない。バックエンド未設置でも編集・録音・転送は利用でき、デバッグだけ理由付きで無効にする。旧版エミュレーターのランタイム依存もクリーンXPで確認する。
- 暫定軽量目標（IDEのみ）: インストーラー10 MB以下、初回ウィンドウ利用可能まで3秒以内、待機時ワーキングセット40 MB以下。基準XP機の構成と測定条件を併記し、エミュレーター起動後の増分は別測定とする。

| TP-03 | **修理済み／代替の物理レコーダー**で既知BASICを2400ボーでテープへ書込み、巻戻して再録音・内容比較し、CF-2000へロードして実行。1200ボーでも標準経路を確認。 | 機材待ち |
| ED-01 | XPの日本語IME、補完、構文色分け、Undo、キーボードでのリボン操作、半角カナとグラフィック文字の実機往復。変換不能文字、未定義行、容量超過を位置付きで表示。 | 未試験 |
| DB-01 | XPのCF-2000構成で、数値・文字列の取得、分岐、自己ループ、コロン複文、`INPUT` 待ち、実行時エラー、切断を試験。対象行への停止とステップが誤らない。 | 未試験 |

回帰試験は **純粋ロジックの自動テスト → 実機採取WAV・CASの固定入力 → XPのGUI／エミュレーター → CF-2000直接接続 → 物理テープ** の順で行う。自作の波形生成と自作の復号だけの往復は、規格への適合を証明しない。独立した実機録音と実機ロード結果を別に使う。音声とデバッグの結果は、実行日・ビルド番号・構成・対象の試験ID・期待結果・実測結果・未達理由を記録する。

| 工程 | 目安 | 実装済みと記録する条件 |
| --- | --- | --- |
| P0 試作 | 1～2週 | 結線、音源の48 kHz、1200／2400の直接往復、XPでのROM起動・行停止・簡単な変数取得を確認。確認できない場合は代替策と時間を再見積もり。 |
| P1 音声・テープ | 2～3週 | 入出力メーター、WinMM、WAV／CAS、標準3形式、エラー処理。AU系とTP-01／02の結果を取得。 |
| P2 エディター・UI | 2～3週 | BASIC解析・補完、トークン化、文字変換、Classicリボン。ED-01の結果を取得。 |
| P3 デバッグ | 2～3週 | 別プロセス連携と行停止・変数表示。DB-01の結果を取得。 |
| P4 配布・全体試験 | 1週～ | XP-01とTP-03を含む全必須項目を合格、使い方と動作確認済み構成を公開。 |

1人開発で約8～12週の暫定見積もり。修理・代替レコーダー調達・ROM準備の待ち時間は含まない。物理テープ未検証の版は `直接転送のプレビュー` と明示し、全要件完了の1.0にはしない。

## 8. 残る判断・参照

1. XP機の音源型番・端子給電・サポートレートとカセットケーブルの結線を確認。マイク直結／適合アダプター／別の音声機器のどれを基準とするかはP0で決定する。
2. 使用権のあるCF-2000 ROMを用意し、公式openMSX 0.12.0 x86で実測。上位バージョンのドキュメントにあるAPIを旧版に仮定しない。
3. 修理するか代替レコーダーを確保するかを決め、物理テープ受入試験に使う構成を記録する。
4. 仕様上の疑義は [MSX Technical Data Book](https://map.grauw.nl/resources/system/msxtech.pdf)、[MSX2 Technical Handbook: Cassette Interface](https://konamiman.github.io/MSX2-Technical-Handbook/md/Chapter5a.html#2-cassette-interface)、[カセット端子](https://www.msx.org/wiki/Data_Recorder_connector)とCF-2000の実測を照合する。
5. ツールチェーンは [Microsoft: XP向けC++ビルド](https://learn.microsoft.com/en-us/cpp/build/configuring-programs-for-windows-xp)、[WinMM waveInOpen](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveinopen)、[Classicコントロール](https://learn.microsoft.com/en-us/windows/win32/controls/cookbook-overview)、[Inno Setup旧版](https://jrsoftware.org/inno-setup/downloads/old)を参照。
6. エミュレーターは [0.12.0公式リリース](https://github.com/openMSX/openMSX/releases/tag/RELEASE_0_12_0)、[同タグのCF-2000設定](https://github.com/openMSX/openMSX/blob/RELEASE_0_12_0/share/machines/National_CF-2000.xml)、[同タグのパイプ制御仕様](https://github.com/openMSX/openMSX/blob/RELEASE_0_12_0/doc/manual/openmsx-control.html)を参照。XP対応が廃止されたのは0.13.0。旧版にCF-2000設定がないという以前の見立ては訂正済み。
