## 2. 主要な設計判断

### 2.1 ポータブルコア＋薄いホスト

`BasicCore` / `TapeCore` は OS API を使いません。ファイルは `IByteReader` /
`IByteWriter` 抽象越しに扱い、Win32 ホストは `CreateFileW`（Unicode パス）の実装を
渡します。これにより Linux 上でコア全体を自動試験できます。コアは C++14 に制限し、
MSVC v141_xp で使えない C++17 ライブラリ（`std::filesystem` 等）を避けています。

### 2.2 BASIC トークン化

MSX BASIC の CRUNCH は「キーワードを識別子の内部でも一致させる」挙動です
（例: `XSIN` は `X` + `SIN`）。ROM と同じ結果を得るため、スキャナは位置ごとに
最長一致でキーワードを探し、識別子を 1 文字ずつコピーします。識別子の途中で
キーワードが一致した場合は警告を出します（黙って壊さない）。

数値の格納:

- 0～9: `0x11+n`
- 10～255: `0x0F, n`
- 256～32767: `0x1C, lo, hi`
- 小数・指数・`!`/`#`: `0x1D`（単精度 BCD 6 桁）/ `0x1F`（倍精度 BCD 14 桁）
- **接尾辞なしの小数は倍精度**（MSX の既定）。`!` で単精度。
- 32768 以上の整数リテラルは倍精度 BCD。
- `&H`/`&O` は `0x0C`/`0x0B`、`&B` は ASCII のまま（仕様・資料どおり）。
- `GOTO`/`GOSUB`/`THEN`/`ELSE`/`RUN`/`RESTORE` などの直後の行番号は `0x0E`。
  `THEN`/`ELSE` は「整数の直後が文末・コロン・ELSE」のときだけ行参照にします。

行参照は静的に検査し、未定義なら警告、範囲外（0～65529）ならエラーにします。
行リンクは `base=0x8000` で計算します。CF-2000 は 16 KB RAM で、起動画面の
`12431 Bytes free` とメモリ配置（`0x8000` 開始、作業領域 0xF71 バイト）が一致します。
ROM はロード時にリンクを再計算するため、値は参考情報でもあります。

`ELSE` は `3A A1`、`'` は `3A 8F E6` として格納します。逆変換では
`3A A1` を `ELSE`、`3A 8F E6` を `'` として表示し、明示的なコロンが先行する
場合は `:ELSE` / `:'` になります。

### 2.3 文字コード

日本語 MSX の文字表は openMSX の `MSXVIDJP.TXT`（2021-11-21）を採用しました。
`0x80-0x9F` と `0xE0-0xFF` にひらがな、`0xA0-0xDF` に半角カナ・記号、
`0x01 + 0x41-0x5F` に GRAPH 文字があります。濁点・半濁点は 2 バイト
（例: `が` = `0x96 0xDE`）で、表示・取込み時は合成します。

- `0x90` と `0xA0` はどちらも全角スペース。書き出しは `0xA0` に正規化。
- `0xFE`/`0xFF` は openMSX 表で未定義。`U+F0FE`/`U+F0FF` の私用領域で
  ロスレスに往復します。
- 全角英数記号（`U+FF01-FF5E`）は半角へ正規化（`！`→`!`）。
- 漢字は CF-2000 の文字表にないため、コンパイル時に **エラー**（`?` 置換なし）。
  PC 上のソースには残せますが、テープへは出力できません。
- MSX の `0x5C` は `¥`。バックスラッシュ `\` は文字列内では表現不能として報告。

### 2.4 テープ信号

MSX2 Technical Handbook Chapter 5 の値をそのまま使い、エミュレーター用の
3744 baud（openMSX の CAS 再生高速化）は実機規格として流用していません。

| 項目 | 1200 baud | 2400 baud |
| --- | --- | --- |
| ビット 0 | 1200 Hz × 1 | 2400 Hz × 1 |
| ビット 1 | 2400 Hz × 2 | 4800 Hz × 2 |
| 1 ビット | 833 µs（40 サンプル @48k） | 417 µs（20 サンプル） |
| 長リーダー | 2400 Hz × 16000（6.67 s） | 4800 Hz × 32000（6.67 s） |
| 短リーダー | 2400 Hz × 4000（1.67 s） | 4800 Hz × 8000（1.67 s） |
| 1 バイト | 0 開始 + 8 データ LSB 先頭 + 1 停止 ×2 | 同左 |

48 kHz ではすべて整数サンプルになります（長リーダー 320000、短 80000）。
生成 WAV の振幅は 14745（約 −7 dBFS）。

CAS は「BIOS 呼出しのバイト列を保存したもの」で、実テープのリーダーは
8 バイトのマーカー `1F A6 DE BA CC 13 7D 74` に置き換わっています。本実装は
CAS → WAV でリーダーとフレームを生成し、WAV → CAS で復号したバイト列の前に
マーカーを挿入します。CAS のマーカーは 8 バイト境界に置き、必要ならデータを
0x00 でパディングします。

### 2.5 復調

48 kHz / 16 bit PCM のみ。ステレオはチャンネル選択。処理:

1. 一次 DC ブロッカー（`y = x - x[-1] + 0.995 y[-1]`）
2. 包絡線から決めるヒステリシス付きエッジ検出
3. エッジ間隔（半周期）を四分の一ビット単位に量子化
4. リーダーの一定間隔連続（60 個以上）から 1200/2400 を判定し、速度を推定
5. ビット積分（0 = 半周期 2 個、1 = 半周期 4 個）→ 11 ビット窓で
   開始ビット 0・停止ビット 1,1 を確認してバイト化。失敗時は 1 ビットずつ
   ずらして再同期
6. 50 ms 以上の無音、または 80 個以上の同一間隔（次の短リーダー）でブロック分割
7. ブロック末尾は、無音で終端エッジが来ない最終ローの半周期を補完して 1 バイトを
   取りこぼさない

自作波形での往復に加え、極性反転・DC オフセット・振幅 0.25 倍・雑音・
1.05 倍の速度変化を自動試験しています。ただしこれは規格適合の証明ではありません。
実機録音には AGC・周波数特性・ドロップアウトがあるため、TP-02 の実測が必要です。

### 2.6 UI（Win32）

仕様の「リボン」は、Classic コモンコントロールのメニュー＋ツールバーで代替しました。
Scintilla は採用せず、XP 標準の RichEdit 2.0（`riched20.dll`）を使っています。
理由: 追加 DLL を配布せず、IME・Undo・Unicode パスを XP 標準で扱えるため。
構文色分けは 300 ms のデバウンス後に `EM_SETCHARFORMAT` で適用します。
補完は `Ctrl+Space` のリストボックス（キーボード操作）です。
ブレークポイント余白・行ステップ・変数表示は P3（openMSX 連携）で実装する範囲で、
この版にはありません。

音声は UI スレッドで待たないよう、録音は専用ライタースレッド、再生は専用再生
スレッドで処理します。録音は 8 個の固定バッファ（各 4096 フレーム）を WinMM に
回し、WAV へストリーム書き込みします。全部が未処理になった場合はバッファ欠落
フラグを立て、正常完了として表示しません。録音形式は 48 kHz モノラルを第一候補、
拒否された場合のみ 48 kHz ステレオを開いて第 1 チャンネルをモノラル化します。

## 4. 試験と検証の境界

自動試験は Linux + GCC 15 で 830 チェック。内容は文字コード全 256 バイト、
BCD、トークン列の既知バイト、逆変換の再トークン化一致、CAS の往復、
1200/2400 の WAV 往復と劣化耐性、WAV 形式検証、日本語を含む全経路です。

一方、次は自動試験では決められません。

- CF-2000 の ROM が本実装のトークン列・行リンク・CAS を実際に `CLOAD` できるか
- XP SP3 のクリーン環境で v141_xp ビルドが起動するか
- 実機の音声レベル・周波数特性・テープ速度に対する余裕
- 日本語 IME、半角カナ、GRAPH 文字の表示・往復
- openMSX 0.12.0 の `-control pipe` と CF-2000 XML の実挙動

これらは `docs/verification.md` の受入試験 ID ごとに「未試験」として残しています。
